## Konsept

En god test er en som _feiler_ når koden er gal. Tester som velger tallverdier der mange operasjoner gir samme resultat (f.eks. 0, 1, 2) kan bestå selv om koden gjør noe feil.

En god test velger verdier der _kun_ riktig atferd gir riktig svar.

## Kode

```java
class StringUtilTest {

    // StringUtil.repeat(s, n) skal returnere s gjentatt n ganger

    @Test
    void testRepeatA() {
        assertEquals("aaa", StringUtil.repeat("a", 3));
    }

    @Test
    void testRepeatB() {
        assertEquals("", StringUtil.repeat("abc", 0));
    }

    @Test
    void testRepeatC() {
        assertEquals("ab", StringUtil.repeat("ab", 1));
    }

    @Test
    void testRepeatD() {
        assertEquals("abab", StringUtil.repeat("ab", 2));
    }
}
```

## Oppgave

Velg de testene som **kan bestå selv om koden returnerer feil svar** (f.eks. returnerer alltid argumentet uendret).

## Valg

- [ ] testRepeatA kan bestå med feil implementasjon
- [x] testRepeatB kan bestå med feil implementasjon
- [x] testRepeatC kan bestå med feil implementasjon
- [ ] testRepeatD kan bestå med feil implementasjon

## Fasit

**B og C kan bestå med feil kode.**

B: En implementasjon som alltid returnerer `""` (tom streng) ville bestå, siden `repeat("abc", 0)` skal gi `""`.

C: En implementasjon som bare returnerer `s` uendret ville bestå, siden `repeat("ab", 1)` = `"ab"`.

A og D krever faktisk repetisjon og avslører feil kode.
