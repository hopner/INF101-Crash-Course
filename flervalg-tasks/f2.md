## Konsept

**Generics** gjør klasser/metoder gjenbrukbare for ulike typer.

**Komposisjon** betyr at en klasse inneholder en annen klasse som felt.

**Encapsulation** er å skjule intern tilstand og bare eksponere det nødvendige via et veldefinert grensesnitt. Disse tre er forskjellige verktøy for forskjellige problemer.

## Kode A

```java
public class Pair<A, B> {
    private final A first;
    private final B second;
    public Pair(A first, B second) { ... }
    public A getFirst() { return first; }
    public B getSecond() { return second; }
}
```

## Kode B

```java
public class Engine { public void start() { ... } }

public class Car {
    private final Engine engine = new Engine();
    public void drive() { engine.start(); ... }
}
```

## Kode C

```java
public class Temperature {
    private double celsius;

    public Temperature(double celsius) {
        if (celsius < -273.15)
            throw new IllegalArgumentException("Under absolutt null!");
        this.celsius = celsius;
    }
    public double getCelsius() { return celsius; }
    public double getFahrenheit() { return celsius * 9/5.0 + 32; }
}
```

- [ ] Polymorfisme
- [ ] Arv
- [ ] Komposisjon
- [ ] Generiske typer
- [x] Encapsulation

## Fasit

**A -> Generiske typer.** Type-parametrene `<A, B>` gjør klassen gjenbrukbar for alle typer.

**B -> Komposisjon.** Car "har en" Engine som felt, den arver ikke fra Engine.

**C -> Encapsulation.** Feltet er privat, konstruktøren validerer ugyldige verdier, og tilstand kan bare endres kontrollert gjennom klassens egne metoder.
