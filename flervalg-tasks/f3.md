## Konsept

Mange teknikker tjener ulike mål. Å vite _hva_ en teknikk løser er like viktig som å vite _hvordan_ den fungerer.

Å velge feil verktøy gir ikke riktig løsning, og på eksamen gir det minuspoeng.

## Hint

**Merk:** Hvert alternativ gir mellom +1 og -1 poeng. Du kan velge mer enn 3, men bare de beste 3 teller (maks 3p). Unngå alternativene du er usikre på.

## Oppgave

Hvilke teknikker er viktigst for å **unngå runtime-bugs**?

## Valg

- [x] Enhetstester (JUnit5)
- [x] Innkapsling / Encapsulation
- [x] Exceptions
- [ ] Versjonskontroll (git)
- [ ] Gode kommentarer
- [ ] Rekursjon
- [ ] God konsistent navngivning

## Fasit

**Beste tre: Enhetstester, Encapsulation, Exceptions.**

Tester avslører bugs _før_ koden når brukeren. Encapsulation hindrer at objekter ender i ugyldig tilstand. Exceptions stopper ugyldig input tidlig og gjør feil synlige.

Versjonskontroll hjelper deg _gjenopprette_ kode, men forebygger ikke bugs i seg selv.
