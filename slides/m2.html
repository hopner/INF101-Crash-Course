Generiske typer

Skriv kode en gang, bruk den for mange typer uten å miste typesikkerhet.

Hvorfor generics?

Kan gi god gjenbruk av kode uten å bruke Object.

class Box<T> {
  private T item;
  public T get() { return item; }
  public void set(T item) { this.item = item; }
}
T er brukt her, men vi kunne i teorien ha brukt et hvilket som helst annet navn. Det er vanlig å bruke T, E, K eller V.

Generics og Grensesnitt

Ingenting stopper deg fra å bruke generics med grensesnitt.

public interface IGrid<E> {
  E get(int row, int col);
  void set(int row, int col, E value);
}

Begrenset generics (bounded)

public <T extends Comparable<T>> T max(T a, T b) {
  return a.compareTo(b) >= 0 ? a : b;
}
  • ->
    Setter krav for hva T kan være.
  • ->
    Typesikkerhet ved kompilering.
  • ->
    Spørsmålstegn ? kan brukes for wildcard-types.

Eksempel på vanskelig metode-signatur

Dette er en tidligere eksamensoppgave, hva betyr egentlig metode-signaturen til Collections.sort()?

public static <T extends Comparable<? super T>> void sort(List<T> list)

    Metoden kan kalles uten å måtte opprette et Collections-objekt.
