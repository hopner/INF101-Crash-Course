Iterable / Iterator / Collections

Hvordan Java går gjennom samlinger.

Iterable og for-each

Dersom en klasse implementerer Iterable, kan den brukes i en for-each-løkke.

public interface Iterable<T> {
    Iterator<T> iterator();
}
MyCollection col = new MyCollection();

for (String s : col) {
    System.out.println(s);
}

Under skallet er dette ekvivalent med:

Iterator<String> it = col.iterator();
String s;
while (it.hasNext()) {
    s = it.next();
    System.out.println(s);
}

Iterator - to metoder

public interface Iterator<E> {
  boolean hasNext();
  E next();
}
Merk: Iterable er samlingen du går gjennom, mens Iterator er objektet som itererer gjennom den.

Comparable vs. Comparator

Comparable<T>

Naturlig rekkefølge

Klassen implementerer compareTo() selv.

Krav:

  • Antisymmetri: Hvis a.compareTo(b) < 0, så må b.compareTo(a) > 0.
  • Transitivitet: Hvis a.compareTo(b) > 0 og b.compareTo(c) > 0, så må a.compareTo(c) > 0.

Comparator<T>

Valgbar rekkefølge

Ekstern sorteringslogikk, dersom man ønsker å sortere etter andre kriterier enn naturlig orden.

Hovedforskjell: Klassen implementerer Comparable selv, mens en Comparator er en separat klasse som implementerer sorteringslogikk.

Collections i Java

  • ->
    List<T>: ordnet, tillater duplikater. Vanlig å bruke ArrayList.
  • ->
    Set<T>: uordnet, tillater ikke duplikater.
  • ->
    Map<K,V>: oppslagsverk mellom en nøkkel og en verdi.
  • ->
    Collections.sort(list) krever at elementene i listen implementerer Comparable.
Tetris: Grid implementerte Iterable<GridCell> for å kunne bruke for-each over cellene i rutenettet.
