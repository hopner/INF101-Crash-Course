Modul 5

Testing med JUnit5

Hva er en god test?

Anatomi til en god test

@Test
void depositIncreasesBalance() {
  // Arrange
  BankAccount acc = new BankAccount(100);

  // Act
  acc.deposit(50);

  // Assert
  assertEquals(150, acc.getBalance(), 0.001);
}
  • ->
    En test, en ting.
  • ->
    Beskrivende testnavn.
  • ->
    Uavhengige tester, kan bruke (@BeforeEach).

Vanlige assertions og annotations

assertEquals(expected, actual);
assertTrue(condition);
assertFalse(condition);
assertThrows(IllegalArgumentException.class, () -> riskyCall());

@Test
@BeforeEach
@AfterEach
@BeforeAll

Hva skal testes?

  • ->
    Ønsket oppførsel.
  • ->
    Grenseverdier.
  • ->
    Ugyldig input (null, negative tall).
  • ->
    Bivirkninger og intern tilstand.
Vanlig feil: bare teste forventet oppførsel eller ugyldig input, viktig å teste hva som skjer i skiftet.

Test-drevet utvikling (TDD)

  • 1
    Skriv en test som feiler.
  • 2
    Skriv minste kode som passerer.
  • 3
    Refaktorer uten å bryte testene.
