Innkapsling

Polymorfisme

Polymorfisme betyr «mange former». En referanse av type A kan peke på et objekt av type B (subtype av A), og kall på metoden vil bruke B sin implementasjon.

interface Shape { double area(); }
class Circle implements Shape { ... }
class Rectangle implements Shape { ... }
Dersom du ønsker å legge til en ny form, kan du opprette en ny klasse som implementerer Shape uten å måtte endre eksisterende kode.

Arv vs komposisjon

Arv - "er en"

extends

Brukes når subklassen er en spesialisering av superklassen.

  • Arver all kode fra superklassen.
  • Kan overskrive metoder.
  • Liskov-substitution-prinsippet.

Komposisjon - "har en"

Felt av annen klasse

Løsere kobling og enklere å bytte implementasjon.

  • Gjenbruker kode ved å benytte objekter av andre klasser.
  • Mer fleksibel enn arv.
  • Unngår problemer med arv som diamantproblemet.

Er du usikker skal du mest sannsynlig velge komposisjon.

Hvordan redusere duplikatkode

  • ->
    Hjelpemetoder. Trekk ut felles logikk til separate metoder.
  • ->
    Arv/abstrakt klasse. Dersom flere klasser deler samme oppførsel, kan du opprette en abstrakt klasse med felles logikk.
  • ->
    Generics. Bruk generics for å skape type-uavhengig kode.
  • ->
    Polymorfisme/interface. Definer felles oppførsel på et sted.
